# KeenZOO

Гибридный проект обхода блокировок для роутеров **Keenetic**
(KeeneticOS + Entware): прозрачный перехват трафика по спискам
доменов, набор туннельных протоколов, отказоустойчивый
контроллер DNS с проверкой DNSSEC и средства управления
(веб-панель и Telegram-бот).

**Версия:** `3.3.14+dns4.2.106.hybrid.ui88` · **IPv4-only** ·
**BusyBox ash** · архитектуры `arm` / `aarch64` / `mips(le)`

---

## 1. Что делает проект

- Поднимает на роутере туннельные протоколы: **Hysteria 2**,
  **Xray (VLESS + Reality)**, **Trojan**, **Shadowsocks**, **Tor**.
- Перехватывает сетевой трафик **только для доменов из списков
  обхода** (остальной трафик идёт напрямую):
  - TCP — `nat/REDIRECT` на локальные порты прокси;
  - UDP — `mangle/TPROXY` (vless, hysteria) либо `nat/REDIRECT`
    (shadowsocks).
- Ведёт списки доменов раздельно по протоколам и обновляет их по
  расписанию.
- Обеспечивает разрешение имён по цепочке с приоритетом
  **валидированных DNSSEC-ответов**, туннельным DNS и аварийным
  режимом с автовыходом.
- Управляет всем этим через **веб-панель (Flask, порт 8080)** и
  **Telegram-бота**: выбор протокола, обновление списков,
  диагностика, генерация конфигураций по шаблонам.
- Устанавливается и обновляется одним скриптом из архива с
  контрольной суммой (`-install` / `-repair`), прогресс и
  достоверный код завершения.

## 3. Перехват трафика (`100-redirect.sh`)

Хук netfilter KeeneticOS, выполняется на событиях сети и по
расписанию; оболочка — BusyBox ash без bash-измов.

- Применяет правила только для доменов из списков `/opt/etc/unblock/`.
- Файл `.disabled` отключает повторную активацию без удаления данных.
- Контракт кодов завершения:
  - **0** — правила применены полностью;
  - **4** — применено **с деградацией**: в
    `/opt/etc/unblock/.tproxy_state` есть строка `fail` (чужой
    ресурс, отвергнутое правило, отсутствие маркера владельца);
    перехват работает частично, причина — в последнем поле строки.
    Это не полный отказ;
  - **75** — общий замок занят другой транзакцией, повтор
    поставлен в очередь;
  - **1** — авария, применённое откатывается снапшотом.

## 4. Контроллер DNS (`utils.py`, блок v4)

Цель — разрешение имён по максимально достоверному пути без
утечек мимо туннеля. Режимы: `LOCAL_DNSSEC`, `TUNNEL_DNS`,
`EMERGENCY_DNS`.

**Политика выбора (по приоритету):**

1. Быстрейший первичный сервер с **валидным DNSSEC**.
2. Следующий быстрейший сервер с валидным DNSSEC.
3. **TUNNEL_DNS** — запрос через активный туннель; порядок
   туннелей: **Hysteria → Xray → Trojan** (`V4_PRIORITY`).
4. **Аварийный режим** — публичные резолверы
   **9.9.9.9 → 8.8.8.8 → 1.1.1.1** (TCP/UDP 53), трафик помечается
   меткой `0x02000104` и ходит прямым путём; при восстановлении
   туннеля происходит **автоматический выход** из аварийного
   режима.

Управление: `--dns-run` (рабочий цикл), `--dns-start`,
`--dns-stop`, `--dns-status`, `--dns-rerank` (пересортировка
кандидатов), `--dns-event`. События пишутся в журнал
`/opt/var/log/unblock_dns_v4.log` (права `0600`).

**Инфраструктура надёжности.** Контроллер защищён единым
атомарным локом `/tmp/keenzoo-dns-v4.lock` с записью владельца
(`lock_owner`, PID + время старта процесса из `/proc/<pid>/stat`).
Санация лока типоспецифична и **самовосстанавливается** при
гонках: чужой каталог снимается рекурсией (свои данные не
трогаются — только `rmdir` пустого), файл и ссылка — поштучно;
проигранная гонка (чужой объект появился между снятием и
открытием) самопочиняется повторной итерацией; после двух неудач
— событие в журнале и управляемый отказ. Каталог журнала
выводится из константы пути (`dirname(V4_LOG)`) — у журнала одна
точка определения.

## 5. Списки обхода и обновления

- Списки `/opt/etc/unblock/<протокол>.txt` — домены, один на
  строку; применяются в `ipset`/`dnsmasq` и в правила перехвата.
- Обновление по расписанию (`/opt/etc/crontab`): ежедневно в 06:00
  и по средам в 03:00 с пересборкой (`REBUILD=1`); вывод крона
  пишется в `/tmp/unblock_update.log` с ограничением размера и
  ротируется `rotate_logs.sh`.
- Бинарники протоколов скачиваются `update_protocols.sh` из
  выпусков GitHub с проверкой целостности; используется совместимый
  с BusyBox вызов `wget`.

## 6. Управление

- **Веб-панель** (`generator.py`, Flask, порт 8080): выбор
  протокола для роутера (`/router/protocol`), запуск обновления
  списков (`/update/run`, статусы), DNS-зонд и статус контроллера
  (`/api/dns-probe`, `/api/dns-status`), PIN-защита. Доступ
  ограничивается подсетями из `bot_config.py`.
- **Telegram-бот**: меню управления протоколами и списками,
  генерация конфигураций по шаблонам (`templates/`), статусы.
- Панель и бот — тонкая надстройка: вся логика применима и без
  них, из консоли и крона.

## 7. Установка и обновление

Поставка — три файла:

- `bypass_project_new.tar.gz` — архив (имя постоянное, члены
  `./opt/…`);
- `bypass_project_new.tar.gz.sha256` — контрольная сумма
  (каноническое имя, публикуется без суффикса `.txt`);
- `INSTALL_HYBRID.txt` — инструкция со всеми командами.

Порядок (подробности — в `INSTALL_HYBRID.txt`): оба файла в
`/tmp`, проверка `sha256sum -c`, извлечение загрузчика
`./opt/bin/deploy_bypass.sh` в `/tmp/keenzoo-bootstrap` и прямой
запуск:

- `-install` — новая установка (дерево, бинарники, конфиги,
  хуки, крон);
- `-repair` — восстановление/обновление поверх существующей
  установки (дерево и бинарники уже стоят — вдвое быстрее).

Установщик пишет снапшот до применения, прогресс идёт и в
терминал, и в лог установки, код завершения достоверен (0 — успех,
ненулевой — отказ с причиной). Отдельные ветки: «применено с
деградацией (код 4)» — не сбой установки; «код 2 апдейтера
протоколов» — подробности в `/tmp/unblock_update.log`.

## 8. Журналы и диагностика

| Путь | Что в нём |
|---|---|
| `/opt/var/log/100-redirect.log` | хук перехвата |
| `/tmp/unblock_update.log` | обновления списков (крон) |
| `/opt/var/log/unblock_dns_v4.log` | события контроллера DNS |
| `logread \| grep -i keenzoo` | системный журнал роутера |
| `/opt/etc/unblock/.tproxy_state` | строки `fail` при деградации перехвата |
| `/tmp/keenzoo-dns-v4.lock` | лок контроллера (владелец, время) |

## 9. Ограничения и принятые решения

- **Только IPv4.** IPv6 в поставке задокументирован как
  уведомление и не используется.
- Оболочка скриптов — **BusyBox ash**; Python-часть — стандартная
  библиотека, зависимости (`flask`, `pyTelegramBotAPI`) ставит
  установщик через `pip`.
- Хук `100-redirect.sh` — часть сетевой инфраструктуры: допустимы
  только правки вокруг временных файлов и уборки, семантика гейта
  и кодов возврата фиксирована.
- Публикуются только архив, сумма и инструкция; дерево разработки
  и регресс-пакет не публикуются (решение владельца).
- История выпусков ведётся в `INSTALL_HYBRID.txt`; версия — в
  `opt/etc/bot/version.md`.

## 10. Регресс-контроль

Каждое изменение проходит полный регресс-сьют в песочнице
(на текущем выпуске — 1646 тестов), включая:

- запуск боевой точки входа `utils.py --dns-run` с инъекциями
  гонок и удалёнными предусловиями;
- стражи поставки: хэш инструкции == фактический хэш архива,
  канонические имена файлов, все пути инструкции существуют в
  дереве или коде;
- линтеры (`py_compile`, `pyflakes`, `ruff`, `dash -n`,
  `busybox ash -n`).

Итоги каждого раунда фиксируются протоколом и описанием
изменений; аппаратная валидация выполняется на целевом роутере
владельцем.
