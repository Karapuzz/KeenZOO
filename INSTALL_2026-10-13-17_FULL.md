# KeenZOO — полная инструкция (релиз 2026-10-13, ред. 17)

Чистая редакция: единый актуальный документ без истории изменений.
Файлы истории (`INSTALL_2026-10-13-16_FULL.md` и ранее, а также эта
инструкция как таковая) выдаются отдельно — в git-дерево и в архив
`opt/` они не входят; это осознанно: архив строго оперирует путями под
`/opt`, а git-репозиторий содержит только исходное дерево. Стендовые
harness-скрипты (f1…f14), упоминаемые в разделе «Проверка», ведутся
локально и тоже не публикуются.

Архив: **`KeenZOO_full_2026-10-13-17.tar.gz`** (коммит `21777db`, корень `opt/`).
SHA-256 архива: `e0d6357842f35c1b12898bb261301df868eb055558951eddc4cf0e1bc3c05675`
(проверка: `sha256sum KeenZOO_full_2026-10-13-17.tar.gz` должен совпасть).

Что внутри: bootstrap Entware с авто-выбором живого зеркала (и
авто-понижением схемы https→http последним шансом — обоснование и
закалка см. в «Замечаниях»), деплой проекта обхода (xray+vision,
dnsmasq-full на ipset, ndm-хуки), Telegram-бот и веб-панель,
FULL/lite-бэкап со штатным восстановлением, ротация логов,
интерактивное меню сценариев (ниже) со сторожами повторной установки,
готовности Entware и **контрактом кода возврата**: «Готово» печатается и
возвращается 0 только при реально развёрнутой базе; частичная установка
— явный «❌ …ЧАСТИЧНО» с кодом 1, одинаково в меню, прямом вызове и
cron (ред. 17). Устаревший iptables-гард UDP/443 под vision-ключ снят:
на ядрах xray ≥ 24 (проверено на 26.10.10) блок QUIC/udp делает само
клиентское ядро по дизайну Vision, а прочий UDP (звонки, медиа, STUN)
идёт через UoT/XUDP — туннель для UDP работает без гардов.

## Меню запуска (интерактивный SSH, без аргумента)

```sh
# на роутере с уже работающей Entware:
sh /opt/bin/entware_bootstrap.sh

# на новом роутере — сначала распаковать архив (раздел A, шаги 1–2),
# bootstrap там ещё не установлен в /opt:
sh /tmp/kz/opt/bin/entware_bootstrap.sh
```

```
═══════════════════ KeenZOO ═══════════════════
 1. Установка Entware (на носитель в файловой системе ext4)
 2. Новая установка (Entware + проект, полная цепочка)
 3. Новая установка (только проект — Entware уже есть)
 4. Обновление рабочего проекта (только проектные файлы)
 5. Восстановление из бэкапа
 6. Создание бэкапа
 0. Выход
═══════════════════════════════════════════════
```

- **1** — только Entware на носитель (запрос пути; пустой ввод = отказ);
- **2** — спрашивает путь, ставит Entware и сразу выполняет за вас шаг 4
  раздела A (деплой свежайшего `/tmp/KeenZOO_full_*.tar.gz`); если цель
  не `/opt` — честная подсказка «проект ставится после монтирования»;
  если архива нет в /tmp — Entware остаётся готовой + предупреждение.
  **Цепочка продолжается только при реально готовой Entware**: инсталлер
  завершился нулём, `bin/opkg` исполняем, `opkg.conf` на месте. Иначе —
  ясная остановка «Entware не готова — проектный deploy пропущен» с
  ненулевым кодом, а не непрозрачный запуск деплоя в пустоту
  (непройденный `opkg update` до монтирования остаётся warning-only, это
  ожидаемо). Deploy, который запускает цепочка, — всегда свежий, из
  распакованного архива; старая копия из `/opt/bin` не выбирается, а
  сбой копирования честно показывается с откатом на локальный скрипт;
- **3** — тот же деплой проекта, но без bootstrap-фазы: для роутеров,
  где Entware уже работает, а нужна именно полная (чистая) установка
  проекта со свежайшего архива из /tmp;
- **4/5/6** — обновление / восстановление из бэкапа / создание бэкапа.

Меню показывается только в интерактивном запуске без аргументов; без
терминала (хуки, cron, pipe) скрипт по-прежнему завершается честным
die-usage и не висит на `read`.

**Итоговый контракт кода возврата (ред. 17).** Любой путь завершения
bootstrap — меню, прямой вызов `sh entware_bootstrap.sh <цель>`, cron —
заканчивается одинаково:

- rc=0 + «Готово. Дальше — …» — база реально развёрнута: инсталлер
  отработал с нулём, `bin/opkg` исполняем, `etc/opkg.conf` непуст и
  содержит строку вида `src/gz entware <url>`; вариант без `opkg update`
  до монтирования — «Готово (opkg update отложен …)», тоже rc=0;
- rc=1 + «❌ Entware развёрнута ЧАСТИЧНО: <причина>» — любое нарушение
  проверок выше (инсталлер упал, нет `bin/opkg`, нет/пустой `opkg.conf`,
  нет `src/gz` в нём); причины перечисляются через «;». Текста «Готово»
  при этом **нет** — автоматика может безопасно ориентироваться и на
  код, и на строку.

Кроме того, при выборе цели `/opt` меню сверяет `/proc/mounts`: если
`/opt` — не точка монтирования (writable-каталог во внутренней flash
роутера), следует предупреждение и явный вопрос «точно ставить туда?
[y/N]». Это защита от заливания Entware во внутреннюю память; запретом
не является — схемы bind-mount/symlink у прошивок разные, поэтому
осознанный ответ `y` пропускается.

### Сторожа повторной установки (предупреждение, не запрет)

Чтобы случайно не запустить полную установку поверх живой системы:

- **проект** (пункты 2 и 3): если найдены маркеры живого деплоя
  (`/opt/bin/deploy_bypass.sh` с +x, `/opt/etc/unblock`, `/opt/etc/bot`),
  меню перечислит находки и потребует ввести `OVERWRITE`; пустой или
  иной ввод — отказ с подсказкой «скорее всего нужно обновление (4) или
  восстановление (5)»;
- **Entware** (пункты 1 и 2, после выбора целевого тома): если в цели
  уже есть `bin/opkg`, в терминале требуется ввести `REINSTALL`; без
  терминала поведение прежнее — только пометка в лог, автоматика не
  ломается.

Осознанная переустановка остаётся возможной: достаточно ввести слово
подтверждения.

## A. Установка на новый роутер (с нуля)

Предусловие: USB-флешка отформатирована в EXT2/EXT3/EXT4 и видна роутеру
(раздел примонтирован — обычно `/opt` после включения сервиса Entware в
интерфейсе Keenetic, либо `/tmp/mnt/<метка>`).

```sh
# 1) Закинуть архив на роутер
scp KeenZOO_full_2026-10-13-17.tar.gz root@192.168.1.1:/tmp/

# 2) Распаковать архив во временный каталог
mkdir -p /tmp/kz && tar xzf /tmp/KeenZOO_full_2026-10-13-17.tar.gz -C /tmp/kz

# 3) Поставить Entware с автофолбэком зеркал
#    (аргумент ОБЯЗАТЕЛЬНЫЙ: /opt — если USB смонтирован как Entware;
#     /tmp/mnt/<метка> — если виден только диск; посмотреть: ls /tmp/mnt/)
sh /tmp/kz/opt/bin/entware_bootstrap.sh /opt
#   или: sh /tmp/kz/opt/bin/entware_bootstrap.sh /tmp/mnt/<метка>
#   Без аргумента в интерактивном SSH скрипт покажет меню:
#   1) Entware на носитель ext4  2) Новая установка (Entware+проект,
#      цепочка)  3) Только проект (Entware уже есть)  4) Обновление
#      5) Восстановление  6) Бэкап
#   Без терминала — честный отказ (не виснет на read).
```

Скрипт сам: определит архитектуру по процессору **и версии ядра** (arm/mips/
x86 × k2.6–k3.10) → переберёт зеркала Entware (канонический
`https://bin.entware.net` — **первым при проверке**, ближайшее к РФ
`entware.diversion.ch` — вторым, китайские — запасом) строгим проходом и
выберет первое живое → развернёт официальный инсталлер **с этого зеркала**
(все прошитые внутри ссылки на `bin.entware.net` заменит на зеркало) →
переключит фиды `opkg.conf` (бэкап — `.bak-keenzoo`) → сделает
`opkg update`. Если ни одно зеркало не ответило строго, последним шансом
включается авто-понижение https→http (покрывает `http://bin.entware.net` и
системы без TLS-стека) — сработавшая схема наследуется в фид.
Предупреждение «opkg update не прошёл» до окончательного монтирования
`/opt` — норма: повторите `opkg update` после монтирования. Финальный
вердикт — по таблице «Итоговый контракт» выше: только «Готово» + rc=0
означает успех.

### Матрица архитектур (ред. 17): `uname -m` → ENTWARE → бинарники

| `uname -m` | Entware-ветка | xray (GitHub asset) | Hysteria 2 |
|---|---|---|---|
| `aarch64` | `aarch64-k3.10` | `arm64-v8a` | `hysteria-linux-arm64` |
| `armv7l`, `armv7`, **`armv8l`** | `armv7sf-k3.2` (ядро 2.6 → `armv7sf-k2.6`) | `arm32-v7a` | `hysteria-linux-arm` |
| `armv6l` | `armv6sf-k3.2` | `arm32-v6` | `hysteria-linux-arm` |
| `armv5tel` | `armv5sf-k3.2` | `arm32-v5` | — |
| `mipsel`, `mipsle`, **`mips64el`**, **`mips64le`** | `mipselsf-k3.4` | `mips32le` | `hysteria-linux-mipsle-sf` |
| `mips`, **`mips64`** | `mipssf-k3.4` | `mips32` | — |
| `i386`, `i686` | `x86-k2.6` | `x86-32` | — |
| `x86_64` | `x64-k3.2` | `x86-64` | `hysteria-linux-amd64` |

Особые случаи (новое в ред. 17):

- **`armv8l`** — 32-битный интерфейс ARMv8: исполняет ARMv7-userland,
  поэтому ветка и бинарные ассёты — как у `armv7l` (включая выбор
  k2.6/k3.2 по версии ядра);
- **`mips64*` на Keenetic** — 32-битный userland на 64-битном ядре:
  endian определяется ELF-пробой («системный» бинарник из `/bin`), далее
  маппинг на соответствующую mips/mipsel-ветку и 32-битный ассёт
  (le→mips32le/mipsle-sf, be→mips32); это покрывает корректные сочетания
  userland/feed/бинарника;
- Неизвестная ISA (вне таблицы) → понятная ошибка на старте bootstrap и
  деплоя. **Updater (ред. 17) ведёт себя мягко для опкевых обновлений**:
  `update_protocols.sh all` на вне-матричной ISA предупредит
  «архитектура вне матрицы бинарников», пропустит xray/hysteria и
  выполнит `opkg`-часть (rc=0); явный запрос бинарника
  (`update_protocols.sh xray|hysteria`) честно откажет с rc=1 —
  скрипт больше не блокируется целиком на экзотике.

### EN-установщики Entware и версия libc (ред. 17)

Upstream entware.net издаёт EN-инсталлеры **не для всех** веток. Bootstrap
имеет явную таблицу (без догадок по имени ветки): кандидаты скачивания —
`EN_<токен>-installer.tar.gz`, затем `<токен>-installer.tar.gz`, где токен —
имя ветки без суффикса `sf`: `aarch64` → `EN_aarch64-installer.tar.gz`,
`mipselsf` → `EN_mipsel-…`, `mipssf` → `EN_mips-…`; для armv5/armv6/armv7,
x86 и x64 EN-установщик **не издаётся** — bootstrap так и сообщает и идёт
штатным минимальным путём (`opkg` + ld/libc с того же зеркала), это не
авария. Если у ветки кандидаты есть, но ни один не скачался — предупреждение
и тот же минимальный путь. Собственное имя можно задать переменной
`INSTALLER_NAME` (обходит таблицу). Версия glibc/ld в минимальном пути
выбирается по ABI-ветке: `*-k2.6` → 2.23, все прочие → 2.27.

Проверка Entware:

```sh
grep -E '^src/gz' /opt/etc/opkg.conf      # фид указывает на ЖИВОЕ зеркало
grep -r bin.entware.net /opt/etc/ || echo 'привязки к мёртвому домену нет'
ls /opt/bin | head
```

# 4) Деплой проекта поверх Entware
#    (если пользовались пунктом 2 меню — это уже сделано цепочкой;
#     пункт 3 делает тот же деплой со свежайшего архива из /tmp)

```sh
mkdir -p /opt/bin
cp /tmp/kz/opt/bin/deploy_bypass.sh /opt/bin/ && chmod +x /opt/bin/deploy_bypass.sh
sh /opt/bin/deploy_bypass.sh /tmp/KeenZOO_full_2026-10-13-17.tar.gz
```

Деплой сам выберет живое зеркало (может отличаться от зеркала бутстрапа,
если то отключилось между шагами — **это штатно, не ошибка**: фиды будут
перезаписаны на то, что живо на момент деплоя).

Проверка проекта:

```sh
ls /opt/etc/init.d/ | grep -E 'S2|S3|S5|S9' ; echo '— сервисы на месте'
iptables -t mangle -L PREROUTING -n | grep TPROXY | head -3
tail -5 /opt/var/log/deploy_bypass.log 2>/dev/null || echo '(лог деплоя — см. вывод экрана выше)'
```

## B. Обновление роутера с уже стоящим проектом

```sh
scp KeenZOO_full_2026-10-13-17.tar.gz root@192.168.1.1:/tmp/
sh /opt/bin/deploy_bypass.sh /tmp/KeenZOO_full_2026-10-13-17.tar.gz
```

Альтернатива через меню: `sh /opt/bin/entware_bootstrap.sh` (без аргументов,
в интерактивном SSH) — меню: пункт 4 (обновление), 5 (восстановление),
6 (бэкап), пункт 3 — полная установка проекта со свежайшего архива из
/tmp (равносильно командам выше); пункт 1 — только Entware на носитель,
пункт 2 — полная цепочка «Entware + проект».

Всё конфигурационное идемпотентно: пользовательские настройки
(`/opt/etc/unblock`, `/opt/etc/bot` и т.п.) не затираются — деплой обновляет
только проектные файлы. `entware_bootstrap.sh` при обновлении **не нужен**
(он только для пустых роутеров).

## C. Бэкап

```sh
sh /opt/bin/backup_project.sh
```

Результат: `/opt/backups/bypass_project_<arch>_<ггггммдд_ччммсс>.tar.gz`
(если `/opt/backups` недоступен — в `/tmp`).

Что попадает в копию:
- `/opt/etc/bot` **целиком** (включая скрытый `.secret_key` — ключ сессий
  веб-панели);
- `/opt/etc/unblock`, `/opt/etc/xray` и прочие конфиги проекта;
- все `/opt/bin/*.sh`, init.d-, ndm-хуки, `rotate_logs.sh`;
- манифест с версиями и sha256 бинарников.

Что НЕ попадает сознательно: бинарники xray/hysteria/tor — десятки МБ и
жёсткая привязка к архитектуре; при восстановлении ставятся ровно тех же
версий по манифесту.

Рекомендация: держите последние 1–2 копии ещё и вне роутера:

```sh
scp 'root@192.168.1.1:/opt/backups/bypass_project_*' .   # забрать локально
```

## D. Восстановление из бэкапа

### D1. Штатное (проект на месте, вернуть конфиги/файлы)

Положите нужный бэкап в `/tmp` или `/opt/backups/` и выполните:

```sh
sh /opt/bin/deploy_bypass.sh -restore
```

Будет выбран **свежайший** снимок (по дате в имени файла; приоритет —
FULL-снимки `keenzoo_full_*`, затем `bypass_project_*`). Чтобы выбрать
конкретную копию — оставьте только её (или положите её позже остальных по
времени в имени).

### D2. Восстановление после полного сброса роутера

Полная цепочка (новый/сброшенный роутер):

```sh
# 1) Entware — см. раздел A, шаги 1–3 (бутстрап со зеркалами)
# 2) Проект — раздел A, шаг 4 (деплой из KeenZOO_full_2026-10-13-17.tar.gz)
# 3) Вернуть свои конфиги и секреты из бэкапа:
scp bypass_project_aarch64-k3.10_XXXXXXXX_XXXXXX.tar.gz root@192.168.1.1:/tmp/
sh /tmp/kz/opt/bin/deploy_bypass.sh -restore     # или /opt/bin/..., если уже скопирован
```

⚠️ Архитектура бэкапа и роутера должна совпадать (в имени файла —
`aarch64-k3.10`, `mipselsf-k3.4` и т.п.): конфиги переносимы, бинарники —
нет (деплой докачает правильные под текущую архитектуру, но манифест
версий валиден только для своей).

### D3. Откат конкретных файлов без полного восстановления

Бэкап — обычный tar.gz с абсолютными путями: достаньте нужное вручную:

```sh
tar tzf /opt/backups/bypass_project_*.tar.gz | grep bot    # что внутри
tar xzf /opt/backups/bypass_project_XXX.tar.gz -C / opt/etc/unblock/xxx.list
```

Если после восстановления что-то не поднялось — стандартный перезапуск:

```sh
for s in /opt/etc/init.d/S*; do "$s" restart; done
```

## Замечания

- **Зеркала**: bootstrap и деплой независимо пробуют список зеркал «на
  живость». Расхождение выбранного зеркала между ними — норма, механизм
  сам держит фиды на доступном зеркале; оригинальный `opkg.conf` навсегда
  лежит в `/opt/etc/opkg.conf.bak-keenzoo`.
- **Схемы http/https**: и в деплое, и в bootstrap `https://bin.entware.net`
  проверяется **первым** (он же канонический источник); `entware.diversion.ch`
  — вторым, дальше китайские зеркала. В bootstrap адрес
  `http://bin.entware.net` покрыт автоматически: авто-понижение схемы
  включается **последним, после всех зеркал** — сначала весь список
  проверяется строго, и только если никто не ответил, те же зеркала
  пробуются с понижением https→http; сработавшая схема наследуется в фид
  `opkg.conf`. Деплой намеренно строже: скачивания только по https
  (политика целостности бинарников), не-https URL там отклоняются.
- **Архитектуры**: bootstrap различает не только ISA (armv5/6/7/8,
  aarch64, mips/mipsel/mips64(el), x86 и x86_64), но и ABI ядра — на
  ARMv7 автоматически выбирается ветка `k2.6` или `k3.2` по мажорной
  версии `uname -r`; чужие ветки дадут SIGILL, поэтому матрица важна и
  сверяется со списком Entware (неизвестная ISA → понятная ошибка на
  старте). Деплой делает то же сопоставление, а при живом
  `/opt/etc/opkg.conf` берёт ветку из фактического `src/gz` — на
  смешанных сетапах (ARMv7 + k2.6) проба зеркала больше не смотрит в
  чужую ветку и не даёт ложных «зеркало недоступно». Полная таблица —
  в разделе A, «Матрица архитектур». HW-оптимизированный ipk-виток
  деплоя (частный случай mipsel-аппаратных ускорителей) осознанно
  оставлен без алиасов mips64*: он действует только на конкретных
  прошивках с таким модулем и самодиагностируется в логе.
- **Закалка bootstrap по схемам и строгий режим**: загрузчик принимает
  только явные `https://`/`http://`; `ftp://`, `file://` и прочие схемы
  отклоняются всегда — такой канал непроверяем. Опциональный
  `KEENZOO_BOOTSTRAP_NO_HTTP=1` честно строгий: запрос идёт только через
  curl с `--proto-redir =https`, wget-фолбэк в этом режиме не
  используется вовсе, а при отсутствии curl установка отказывает до
  первого сетевого вызова с подсказкой поставить curl или снять флаг.
  После подмены base URL в инсталлере при NO_HTTP=1 проверяется **всё**
  дерево распаковки (не только файлы с упоминанием bin.entware.net):
  любая уцелевшая http://-ссылка = отказ до запуска непроверенного кода.
- **Почему http-downgrade остаётся включённым по умолчанию**: часть
  целевых устройств имеет BusyBox wget без TLS-стека; жёсткий запрет
  сделал бы установку на них невозможной. Механика осознанная: все
  зеркала сначала проверяются строго по https, понижение — только
  последним проходом, сработавшая схема наследуется в фид, а кто хочет
  гарантии — поднимает `KEENZOO_BOOTSTRAP_NO_HTTP=1` и/или пин
  `KEENZOO_BOOTSTRAP_SHA256=<хэш>` (обе опции fail-closed: отказ этих
  проверок останавливает установку до распаковки/запуска). Обязательного
  пина по умолчанию нет, потому что upstream entware.net не публикует ни
  подписи, ни хэши инсталлера — прошитый в код TOFU-пин не защитил бы
  первую установку, а после каждого обновления апстрима ломал бы все
  последующие.
- **dnsmasq**: проект требует `dnsmasq-full` (ipset). Если в отчёте
  обновлений «n/a»/пусто: `opkg update && opkg install --force-reinstall
  dnsmasq-full`, затем проверка `dnsmasq --version | grep -o ipset` и
  перезапуск `/opt/etc/init.d/S56dnsmasq restart` + `unblock_update.sh`.
- **vless+vision и UDP (актуально, 2026-10-12)**: гард UDP/443 из хука
  убран — его функцию выполняет само ядро xray (≥ 24.x). Если на
  роутере старые релизы проекта ставили этот DROP, он стирается
  автоматически ближайшим прогоном ndm-хука (переподключение
  интерфейса/рестарт сервиса/перезагрузка), руками ничего не нужно.
  Проверка состояния ядра: `xray version`. Если после обновления
  WhatsApp/медиа всё же не грузятся — диагностику начинайте с
  `xtls-rprx-vision-udp443`-вариантов ключей и версии ядра, не с сети.
- **Быстрая самодиагностика**: `sh /opt/bin/test_udp_tunnels.sh` и
  `sh /opt/bin/dns_spoof_check.sh`.
- Логи ротируются автоматически (`/opt/bin/rotate_logs.sh` в cron проекта),
  бэкапы не накапливаются сами по себе — периодически чистите старые
  `/opt/backups/bypass_project_*.tar.gz`, оставляя 2–3 свежих.
