Архив: **`KeenZOO_full_2026-10-13-11.tar.gz`** (коммит `66517c2`, корень `opt/`).
SHA-256 архива: `21e27fa53dd181a3df596f0ebba149f2c7a9dabc5a6b55425cf830f14ffd837d`
(проверка: `sha256sum KeenZOO_full_2026-10-13-11.tar.gz` должен совпасть).
Включает всё накопленное: автофолбэк зеркал Entware (и в деплое, и в
бутстрапе), FULL/lite-бэкап и восстановление, ротацию логов. Снят

**Редакция 11 (коммит F9, HEAD `f98eb82`) — закрытие аудита rev10
(HIGH-1, MEDIUM-1/2, LOW-1/2).** Пять находок подтверждены чтением и
harness'ами; две были собственными регрессиями пакетов F7/F8 (буквальный
постчек ARGS и двойное экранирование в raw-шаблоне), в rev10 они
проявлялись на реальной системе: ложный ❌ на каждом успешном opkg-пути
xray и литеральные `\u26A0'ы` в панели.

- **HIGH-1 (NO_HTTP как гарантия).** `dl_file()` обслуживал явно заданный
  `http://`-URL до проверки `KEENZOO_BOOTSTRAP_NO_HTTP=1` (та стояла
  только перед auto-downgrade), а `curl -L` молчаливо принимал редирект
  https→http. Теперь http-вход в параноидальном режиме отсекается ДО
  сетевого обращения; для https добавлен `--proto-redir =https`
  (busybox wget флага не имеет, документировано). Opt-in пин:
  `KEENZOO_BOOTSTRAP_SHA256=<hex>` сверяется после integrity-гейта —
  доверенный источник выбирает сам пользователь/CI (upstream подписей не
  публикует; TOFU-пин в коде первую установку не защитил бы). И любая
  выжившая после подмены ссылка на bin.entware.net в инсталлере —
  честный die до запуска. Дефолтное понижение https→http последним
  шансом — по проектному констрейнту не трогаем.
- **MEDIUM-1 (семантический постчек).** В rev10 normalize считал форму
  `ARGS="run -confdir /opt/etc/$PROCS"` уже корректной (значение
  совпадает) и не переписывал, а постчек искал буквальную строку с
  `xray` — на штатном opkg-обновлении был ложный «не нормализован» и
  _rc=1. `init_args_value_ok()` (common.sh) сравнивает значения с
  раскрытием PROCS и требует их у обеих сторон. Техническая тонкость:
  в двойных кавычках от shell-экспансии $ экранирует `\$`, перенос `\\`
  усечёт regexp — прокомментировано в коде. В fake-opkg стенд добавлена
  pkgform-E2E-регрессия («пакет оставил init без изменений»).
- **MEDIUM-2 (одиночные IP — паритет).** `cidr_policy_ok_py` работал
  только для CIDR: 10.0.0.1 «сохранялся» в панели/боте, а runtime
  (is_public_ipv4, обе фазы ложат одиночные IP только через
  unblock_ipset.sh) его молча отбрасывал у ЛЮБОГО набора. Теперь паритет
  public-only + понятная ошибка с подсказкой формата: приватный host в
  VPN — однохостовым CIDR `10.0.0.1/32` (vpn-политика для подсетей
  легальна и сегодня).
- **LOW-1 (raw-шаблон).** `PAGE_TEMPLATE = r'''...'''` — Python
  raw-строка, а JS-правки писали ДВОЙНЫЕ слеши: в браузер доходил regex
  `\\s` (снятие префикса «ok; » не срабатывало) и литеральные
  `\\u26A0`/`\\u2705` вместо значков. Одиночные слеши; добавлен
  побайтовый тест + node-проверка префикса.
- **LOW-2 (атомарный rename).** временный файл normalize теперь в
  каталоге init-файла + `mv -f` (rename в одной ФС атомарен); cross-FS
  `cp` из /tmp не был атомарным. Проверки rc/harness-политики rev10
  сохранены.

**Редакция 10 (коммит F8, HEAD `dde326d`) — проверка и закрытие аудита-6
(HIGH-1/2, MEDIUM-1..6, LOW-1/2).** Все десять находок валидированы
чтением кода перед правкой — реальные регрессии подтвердились, включая
две, внесённые предыдущими пакетами (LOW-1 панели и недоопределённое
hostname-патчирование зеркал вида host/entware):

- **HIGH-1 (bootstrap endian).** uname «mips» у Keenetic не значит
  big-endian: на LE-системе bootstrap радостно ставил mipssf-инсталлер,
  и чистая установка получала неработающий Entware. Локальная
  `_bs_detect_endian` читает байт EI_DATA (offset 5) первого доступного
  бинарника (1=LE/2=BE) + /proc/cpuinfo-фолбэк; unknown = честный отказ
  до записи на флешку (`opt/bin/entware_bootstrap.sh`).
- **HIGH-2 + MEDIUM-1 (base URL инсталлера).** generic.sh ссылается на
  `http://bin.entware.net/...`: прежний патч менял только hostname —
  `${MIRROR_HOST}` без пути терял `/entware` у «path-based» зеркал, а
  http-схема выживала даже при `KEENZOO_BOOTSTRAP_NO_HTTP=1` (payload
  после верифицированного тарбала всё равно шёл по HTTP). Теперь
  подменяется ПОЛНЫЙ base (схема+хост+путь) на выбранный ENTWARE_BASE;
  после патча при NO_HTTP=1 наличие выживших http:// ссылок — отказ.
  **Ограничение по подписи**: upstream не публикует хэшей/подписи
  инсталлера, пиннингу неоткуда взяться офлайн; сохранён integrity-гейт
  (tar tzf + размер) — враждебное зеркало может подменить payload
  целиком, это осознанный компромисс Entware-дистрибуции, зафиксирован
  явно.
- **MEDIUM-2 (JSON заглушек).** alpn для Hysteria вставлялся в массив
  сырым — рендерился невалидный `[h3]`, сервис не стартовал с первой
  установки. Значение-заглушка теперь с кавычками (`"h3"`), а рендер
  шаблона валидируется `python3 -m json.tool` до записи (битый файл в
  цель не попадает; без python3 проверка тихо пропускается)
  (`opt/bin/deploy_bypass.sh`).
- **MEDIUM-3 (VPN-CIDR по диапазону).** vpn-ветка `cidr_policy_ok`
  смотрела лишь на первый октет: 128.0.0.0/1 проходил (охватывает
  мультикаст), а эквивалентный 224.0.0.0/0 отклонялся. Единый механизм
  `_cidr_no_overlap` на awk — весь диапазон [network..broadcast]
  пересекается с deny-list: для vpn — только 224.0.0.0/3, для статики —
  полный служебный список (is_public_cidr на том же механизме)
  (`opt/bin/common.sh`).
- **MEDIUM-4 (паритет панели).** python-валидатор бота принимал `/0` и
  приватные сети — runtime их молча отбрасывал: в панели «записано», в
  обходе пусто. `cidr_policy_ok_py` повторяет shell-политику с понятной
  причиной отказа (`opt/etc/bot/lists_core.py`).
- **MEDIUM-5 (OUTPUT-anchor).** проверка provisioning'а unblockrouter
  грепала весь nat-дамп — правило в PREROUTING маскировало потерю
  обязательного OUTPUT-правила. Якорь `'^-A OUTPUT '` (`opt/bin/unblock_update.sh`).
- **MEDIUM-6 (честные rc).** `normalize_init_args` обязал ошибки записи
  и при любом раскладе пел «восстановлено» — на недоступном /opt чужие
  ARGS жили молча. Рендер во временный файл → проверка непустого →
  `cp -f`, rc≠0 + сообщение при отказе; S24xray-ARGS дополнительно
  фиксируются grep'ом после clean во всех трёх успешных ветках
  auto-updater'а (`opt/bin/common.sh`, `opt/bin/update_protocols.sh`).
- **LOW-1 (UI).** замена `/^ok;\s*/` оставляла голое «ok» — и оно само
  становилось жёлтым предупреждением на каждом чистом успехе (ловушка
  regex-подхода). Явное сравнение до замены (`opt/etc/bot/generator.py`).
- **LOW-2 (старт).** pidof один раз через ровно 1 с валил медленные
  MIPS/ARM: опрос до 5 × 1 с (`opt/bin/update_protocols.sh`).

**Редакция 9 (коммит F7, HEAD `66517c2`) — закрытие аудита rev5
(High #1/#2, Medium #3–#8, Low #9–#11) + урок «краткого» отчёта.**
Отчёт rev5 снят уже с правильного архива ред. 8, и его находки были

  не как «мёртвый процесс». Сервис перезапускается лишь когда обновление
  действительно было (на «уже актуален» простоя нет вообще).
- **#7: статус `running` больше не зависает на сигналах.** Один
  `trap cleanup EXIT` плюс сами сигналы в явных кодах (130/143/129):
  TERM посреди прогона теперь ASшно даёт rc=143 и `{"status":"error",

  через pkill). Раньше cleanup на `EXIT INT TERM HUP` под BusyBox ash

- **#1: предупреждения VERIFIER'а видны в панели.** Статус остаётся

  но `message` уже всегда нёс подробности — панель просто его
  игнорировала. Теперь `done` с непустым текстом (после обрезки «ok; »)
  рисует жёлтую плашку «Готово, с предупреждением: RULES MISSING: …»,
  зелёная — только при чистом `ok`.
- **#8: VPN-connected переустанавливает три таблицы.** На событии
  подключения VPN ifstatechanged-хук зовёт `100-redirect.sh` с

  не запускает mangle при этом событии, MARK/CONNMARK-правила VPN
  появляются без ожидания движения WAN. Сопутствующий бонус: mangle-прогон

## A. Установка на новый роутер (с нуля)

Предусловие: USB-флешка отформатирована в EXT2/EXT3/EXT4 и видна роутеру
(раздел примонтирован — обычно `/opt` после включения сервиса Entware в
интерфейсе Keenetic, либо `/tmp/mnt/<метка>`).

```sh
# 1) Закинуть архив на роутер
scp KeenZOO_full_2026-10-13-11.tar.gz root@192.168.1.1:/tmp/

# 2) Распаковать архив во временный каталог
mkdir -p /tmp/kz && tar xzf /tmp/KeenZOO_full_2026-10-13-11.tar.gz -C /tmp/kz

# 3) Поставить Entware с автофолбэком зеркал
#    (если USB смонтирован в /opt — аргумент не нужен;
#     иначе укажите точку монтирования)
sh /tmp/kz/opt/bin/entware_bootstrap.sh
#   или: sh /tmp/kz/opt/bin/entware_bootstrap.sh /tmp/mnt/<метка>
```

Скрипт сам: определит архитектуру по процессору **и версии ядра** (arm/mips/
x86 × k2.6–k3.10) → переберёт зеркала Entware (канонический
`https://bin.entware.net` — **первым при проверке**, ближайшее к РФ
`entware.diversion.ch` — вторым, китайские — запасом) строгим проходом и
выберет первое живое → развернёт официальный инсталлер **с этого зеркала**
(все прошитые внутри ссылки на `bin.entware.net` заменит на зеркало) →
переключит фиды `opkg.conf` (бэкап — `.bak-keenzoo`) → сделает
`opkg update`. Если ни одно зеркало не ответило строго, последним шансом
включается авто-понижение https→http (покрывает `http://bin.entware.net` и
системы без TLS-стека) — сработавшая схема наследуется в фид.
Предупреждение «opkg update не прошёл» до окончательного монтирования
`/opt` — норма: повторите `opkg update` после монтирования.

Проверка Entware:

```sh
grep -E '^src/gz' /opt/etc/opkg.conf      # фид указывает на ЖИВОЕ зеркало
grep -r bin.entware.net /opt/etc/ || echo 'привязки к мёртвому домену нет'
ls /opt/bin | head
```

## C. Бэкап

```sh
sh /opt/bin/backup_project.sh
```

Результат: `/opt/backups/bypass_project_<arch>_<ггггммдд_ччммсс>.tar.gz`
(если `/opt/backups` недоступен — в `/tmp`).

Что попадает в копию:
- `/opt/etc/bot` **целиком** (включая скрытый `.secret_key` — ключ сессий
  веб-панели);
- `/opt/etc/unblock`, `/opt/etc/xray` и прочие конфиги проекта;
- все `/opt/bin/*.sh`, init.d-, ndm-хуки, `rotate_logs.sh`;
- манифест с версиями и sha256 бинарников.

Что НЕ попадает сознательно: бинарники xray/hysteria/tor — десятки МБ и
жёсткая привязка к архитектуре; при восстановлении ставятся ровно тех же
версий по манифесту.

Рекомендация: держите последние 1–2 копии ещё и вне роутера:

```sh
scp 'root@192.168.1.1:/opt/backups/bypass_project_*' .   # забрать локально
```

## D. Восстановление из бэкапа

### D1. Штатное (проект на месте, вернуть конфиги/файлы)

Положите нужный бэкап в `/tmp` или `/opt/backups/` и выполните:

```sh
sh /opt/bin/deploy_bypass.sh -restore
```

Будет выбран **свежайший** снимок (по дате в имени файла; приоритет —
FULL-снимки `keenzoo_full_*`, затем `bypass_project_*`). Чтобы выбрать
конкретную копию — оставьте только её (или положите её позже остальных по
времени в имени).

### D2. Восстановление после полного сброса роутера

Полная цепочка (новый/сброшенный роутер):

```sh
# 1) Entware — см. раздел A, шаги 1–3 (бутстрап со зеркалами)
# 2) Проект — раздел A, шаг 4 (деплой из KeenZOO_full_2026-10-13-11.tar.gz)
# 3) Вернуть свои конфиги и секреты из бэкапа:
scp bypass_project_aarch64-k3.10_XXXXXXXX_XXXXXX.tar.gz root@192.168.1.1:/tmp/
sh /tmp/kz/opt/bin/deploy_bypass.sh -restore     # или /opt/bin/..., если уже скопирован
```

⚠️ Архитектура бэкапа и роутера должна совпадать (в имени файла —
`aarch64-k3.10`, `mipselsf-k3.4` и т.п.): конфиги переносимы, бинарники —
нет (деплой докачает правильные под текущую архитектуру, но манифест
версий валиден только для своей).

### D3. Откат конкретных файлов без полного восстановления

Бэкап — обычный tar.gz с абсолютными путями: достаньте нужное вручную:

```sh
tar tzf /opt/backups/bypass_project_*.tar.gz | grep bot    # что внутри
tar xzf /opt/backups/bypass_project_XXX.tar.gz -C / opt/etc/unblock/xxx.list
```

Если после восстановления что-то не поднялось — стандартный перезапуск:

```sh
for s in /opt/etc/init.d/S*; do "$s" restart; done
```

## Замечания

- **Зеркала**: bootstrap и деплой независимо пробуют список зеркал «на
  живость». Расхождение выбранного зеркала между ними — норма, механизм
  сам держит фиды на доступном зеркале; оригинальный `opkg.conf` навсегда
  лежит в `/opt/etc/opkg.conf.bak-keenzoo`.
- **Схемы http/https**: и в деплое, и в bootstrap `https://bin.entware.net`
  проверяется **первым** (он же канонический источник); `entware.diversion.ch`
  — вторым, дальше китайские зеркала. В bootstrap адрес
  `http://bin.entware.net` покрыт автоматически: авто-понижение схемы
  включается **последним, после всех зеркал** — сначала весь список
  проверяется строго, и только если никто не ответил, те же зеркала
  пробуются с понижением https→http; сработавшая схема наследуется в фид
  `opkg.conf`. Деплой намеренно строже: скачивания только по https
  (политика целостности бинарников), не-https URL там отклоняются.
- **Архитектуры**: bootstrap различает не только ISA (armv5/6/7/8, aarch64,
  mips/mipsel/mips64(el), x86 и x86_64), но и ABI ядра — на ARMv7
  автоматически выбирается ветка `k2.6` или `k3.2` по мажорной версии
  `uname -r`; чужие ветки дадут SIGILL, поэтому матрица важна и сверяется
  со списком Entware (неизвестная ISA → понятная ошибка на старте).
- **dnsmasq**: проект требует `dnsmasq-full` (ipset). Если в отчёте
  обновлений «n/a»/пусто: `opkg update && opkg install --force-reinstall
  dnsmasq-full`, затем проверка `dnsmasq --version | grep -o ipset` и
  перезапуск `/opt/etc/init.d/S56dnsmasq restart` + `unblock_update.sh`.
- **vless+vision и UDP (актуально, 2026-10-12)**: гард UDP/443 из хука
  убран — его функцию выполняет само ядро xray (≥ 24.x). Если на
  роутере старые релизы проекта ставили этот DROP, он стирается
  автоматически ближайшим прогоном ndm-хука (переподключение
  интерфейса/рестарт сервиса/перезагрузка), руками ничего не нужно.
  Проверка состояния ядра: `xray version`. Если после обновления
  WhatsApp/медиа всё же не грузятся — диагностику начинайте с
  `xtls-rprx-vision-udp443`-вариантов ключей и версии ядра, не с сети.
- **Быстрая самодиагностика**: `sh /opt/bin/test_udp_tunnels.sh` и
  `sh /opt/bin/dns_spoof_check.sh`.
- Логи ротируются автоматически (`/opt/bin/rotate_logs.sh` в cron проекта),
  бэкапы не накапливаются сами по себе — периодически чистите старые
  `/opt/backups/bypass_project_*.tar.gz`, оставляя 2–3 свежих.

Прогон перед сдачей: архив собран из git HEAD (коммит `a77628d`,
`opt/`-корень, 58 путей, 24 исполняемых), `sh -n`/`bash -n` по всем
скриптам чист, `py_compile` всех 6 модулей бота чист. Полный цикл
рендера: все 4 JSON-шаблона подстановок парсятся как валидный JSON;
рендер vless-конфига проверен на **реальном xray 26.3.27**
(`run -test` → «Configuration OK», живой старт 4 с → слушатели
tcp+udp :10810 поднялись, ошибок в логе нет). Кросс-файловые сцепки:
порты 10810/10829/10830 совпадают в хуке, init.d и тесте; ipset-наборы
создаются unblock_ipset (hash:net) — используются хуком по тем же
именам; INIT_* в хуке ссылаются на существующие init-файлы; статические
пути BACKUP_ITEMS присутствуют (динамические — штатно runtime-only,
скрипт пропускает отсутствующие). Стенды: (1) порядок зеркал —
`bin.entware.net` первым; (2) мёртвый https пропускается, явный http
подхватывается; (3) авто-понижение https→http — последним проходом;
(4) свип 16 ISA×kernel матрицы; (5) полный EN-прогон aarch64; (6) блока
гардов: добавлений vision-гарда — 0, legacy-удаления — есть, troj/tor
нетронуты; (7) перезапись opkg-фида: на всех 4 реалистичных конфигах
внешняя ветка архитектуры (включая k2.6) сохраняется, префиксы зеркал
не клеятся — найденный тут latent-баг раннего sed исправлен.
